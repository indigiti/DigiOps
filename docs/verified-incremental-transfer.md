# Verified incremental artifact transfer (QNeXT pilot)

The remote control plane still downloads and verifies the complete GitHub artifact. For QNeXT remote targets only, an upgraded agent can advertise `delta-transfer-v1`. The controller asks for a content-chunk index of the last successfully deployed, verified ZIP, creates a bounded exact-byte patch if it saves at least 5%, and transfers that patch through the existing signed chunked-upload API. The agent binds the cache to its current release, checks the patch transport digest, reconstructs the original ZIP in the incoming directory, checks every chunk and the final SHA-256 against the approved original artifact, then calls the unchanged publication pipeline. The source ZIP is not altered and rollback snapshots remain complete.

Compatibility: old agents, empty/stale caches, archives above 64 MiB and inefficient deltas use full uploads. A cache is populated only after a verified successful deploy. A cache failure is nonfatal. Rollback invalidates a mismatched cache. No retry is attempted after a potentially uncertain commit; inspect deployment status before retrying. Corrupt or missing bases at commit fail before publication; retry explicitly with a full archive once the state is resolved (authenticated deploy API: boolean `forceFull: true`).

Scope: this reduces control-plane-to-remote transfer, not GitHub artifact size, CI build time or runtime activation. Local deployment is unchanged. No service restart is suppressed: QNeXT currently embeds the release commit in Market Core and requires a separate runtime identity and compatibility contract before component-only activation. Upgrade the control plane and target agent separately, verify agent capability using the existing target test, perform one successful full deploy to seed the cache, then verify subsequent transfer mode/bytes and exact release identity. All releases continue to use the existing deploy and rollback mechanism.

Security: HMAC authenticated requests; private project-scoped cache; 64 MiB archive bound; maximum 4096 chunks and 1 MiB patch header; no paths supplied by patches; exact approved ZIP hash checked before publication. A malformed or ineffective patch is not a deployable release.
